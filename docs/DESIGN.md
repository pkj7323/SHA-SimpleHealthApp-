# 화면 설계 규칙 — 토스·인아웃처럼 보이게 하는 법

`DIET-REDESIGN.md`가 "끼니를 어떤 구조로 담을지"를 정했다면 이 문서는 **"그걸 어떻게 보여줄지"**
를 정한다. 기능 문서가 아니라 **검사표**다.

## 이 문서가 있는 이유

"깔끔하게 만들어줘"는 지시가 아니다. 깔끔함은 **원인이 아니라 결과**다 — 지키는 규칙이
적고 일관돼서 깔끔해 보이는 것이지, 깔끔하게 만들려고 해서 깔끔해지는 게 아니다.
형용사를 주면 만들 때마다 다른 게 나오고, 나온 걸 보고 "이건 아닌데"라고밖에 말할 수 없다.

그래서 여기 적힌 건 전부 **세거나 재서 지켰는지 확인할 수 있는 것**이다.
"여백을 넉넉히"가 아니라 `20dp`, "버튼을 눈에 띄게"가 아니라 `한 화면에 채운 버튼 하나`.

작업을 시킬 때는 이렇게 말하면 된다: **"운동 탭을 `docs/DESIGN.md`에 맞춰 고쳐줘."**

---

## 결정 요약

| 항목 | 결정 |
|---|---|
| 색 | 중립 회색 계단 + **강조색 하나**(라임). 강조색은 "지금 누를 것"과 "지금 상태"에만 |
| 배경 | 흰색 계열 한 톤. 카드는 그보다 아주 살짝 어두운 회색. **M3 기본 보라 틴트를 끈다** |
| 구분선 | **쓰지 않는다.** 나누는 일은 여백과 카드가 한다 |
| 글자 크기 | **네 단계만**. 숫자는 크고 굵게, 이름표는 작고 흐리게 |
| 버튼 | 한 화면에 **채운 버튼 하나**. 나머지는 글자 버튼이거나 그냥 누르는 줄 |
| 여백 | 4의 배수. 화면 좌우 여백 `20` 고정 |
| 모서리 | 카드 `16`, 버튼 `14`, 칩 `999`(알약) |
| 그림자 | 안 쓴다. 높이 차이는 배경색으로만 |
| 정렬 | 전부 왼쪽. 숫자만 오른쪽 |

## 1. 지금 화면의 문제 (고칠 대상)

새로 만들기 전에 **무엇이 어긋나 있는지**부터 이름을 붙여둔다. 이게 있어야 "고쳤다"를
확인할 수 있다.

1. **테두리 버튼이 전부다.** `루틴 선택`·`종목 추가`·`루틴으로 저장`·`음식 추가`·`내 식사`·
   `목표`·날짜가 전부 `OutlinedButton`이다. 다 같은 무게라 **무엇이 중요한지 화면이 말하지
   않는다.** 눈이 갈 곳을 못 정하고 훑게 된다.
2. **M3 기본 색을 그대로 쓴다.** `Theme.kt`가 `primary`만 바꾸고 `surface`/`background`를
   안 정해서 배경에 **보라 틴트**가 깔린다. 초록 강조색과 보라 바탕이 서로 싸운다.
3. **글자가 전부 같은 크기다.** 끼니 카드 안 "합계 692kcal · 단백질 65g …"이 이름과 같은
   급으로 적혀 있다. **이 앱의 내용은 숫자인데 숫자가 안 보인다.**
4. **구분선으로 나눈다.** 헤더 아래 `HorizontalDivider`가 있고 카드 안에도 있다. 선이
   많을수록 화면이 잘게 쪼개져 복잡해 보인다.
5. **밀도가 제각각이다.** 세트 줄은 40dp로 빡빡한데 끼니 카드는 헐렁하다.
6. **버튼을 가로로 둘씩 놓아 글자가 접힌다.** `루틴으로 저장`이 두 줄이 되거나 잘린다.

## 2. 색

### 2.1 값

아이콘에서 가져온다. 아이콘과 앱이 같은 색을 써야 같은 물건으로 보인다.

```
라임   #6FE26C   강조. 지금 누를 것 / 지금 진행 중인 것
잉크   #16150F   글자·아이콘 (검정 대신. 순검정은 딱딱하다)
```

밝은 테마 중립색:

```
배경    #FFFFFF
카드    #F5F6F4      배경보다 아주 살짝 어둡게. 이 차이만으로 층을 만든다
경계    (없음)
글자1   #16150F      제목·숫자
글자2   #6B6F68      이름표·설명
글자3   #A3A79F      비활성
위험    #E5484D      삭제 확인에만
```

어두운 테마는 배경 `#16150F`, 카드 `#22211B`, 글자1 `#F5F6F4`, 글자2 `#9A9E96`.
**라임은 양쪽에서 같은 값을 쓴다** — 브랜드 색이 테마 따라 변하면 브랜드가 아니다.

### 2.2 규칙

- **강조색은 화면당 한 곳이 원칙이다.** 두 곳을 넘어가면 강조가 아니다.
- 강조색을 쓰는 자리: 채운 버튼 하나 / 진행 막대 / 켜진 스위치 / 선택된 탭.
- **회색으로 되는 일에 색을 쓰지 않는다.** 지금 잘 하고 있는 것(체크된 세트 등)에만.
- `MaterialTheme.colorScheme`의 `surface`·`background`·`surfaceVariant`를 **반드시 직접
  정한다.** 안 정하면 M3가 보라 틴트를 깔고, 그게 지금 화면이 애매해 보이는 가장 큰 이유다.

---

## 3. 글자

네 단계뿐이다. 여기 없는 크기는 쓰지 않는다.

| 이름 | 크기/굵기 | 쓰는 곳 |
|---|---|---|
| 화면 제목 | 24 / Bold | 화면 맨 위 한 줄 (`설정`, `히스토리`) |
| 값 | 20–28 / Bold | **숫자.** 오늘 섭취 kcal, 운동 시간, 남은 휴식 |
| 본문 | 16 / Medium | 항목 이름 (`아침`, `바벨 벤치프레스`) |
| 이름표 | 13 / Regular / 글자2 | 설명·단위·보조 정보 |

규칙:

- **숫자와 이름표를 붙여 쓸 땐 숫자가 위, 이름표가 아래.** 큰 것부터 읽힌다.
- 단위(`kcal`, `kg`, `g`)는 숫자보다 **한 단계 작고 흐리게.** `692`가 주인공이고
  `kcal`은 거들 뿐이다.
- 모르는 값은 `?`로 적는다(기존 규칙). `?`도 값이므로 값 단계로 적는다.
- 한 카드 안에서 본문 크기가 두 종류 나오면 잘못 만든 것이다.

---

## 4. 간격과 크기

- 모든 간격은 **4의 배수**. `4 8 12 16 20 24 32`만 쓴다.
- **화면 좌우 여백 `20` 고정.** 카드도, 제목도, 목록도 전부 이 선에서 시작한다.
  선이 안 맞는 게 어수선함의 절반이다.
- 카드 안 여백 `16`. 카드끼리 간격 `12`.
- 화면 제목 아래 `16`, 문단(카드 묶음) 사이 `24`.
- **누르는 것은 최소 높이 `48`.** 세트 줄의 작은 버튼도 이 규칙 아래로 내려가지 않는다.
- 목록 한 줄 높이 `56` 이상.

## 5. 부품별 규칙

### 5.1 버튼

| 종류 | 모양 | 언제 |
|---|---|---|
| 주 버튼 | 라임 채움, 높이 `52`, 모서리 `14`, 가로 꽉 | 화면에서 제일 하고 싶은 일 **하나** |
| 글자 버튼 | 배경 없음, 잉크 글자 | 나머지 전부 |
| 칩 | 알약, 높이 `36` | 고르는 것 (날짜, 분류) |

- **한 화면에 주 버튼은 하나.** 두 개가 필요하면 하나는 글자 버튼이다.
- **테두리 버튼(`OutlinedButton`)은 쓰지 않는다.** 지금 화면이 밋밋한 주범이다.
- 버튼을 가로로 둘 놓지 않는다. 세로로 쌓거나, 하나를 글자 버튼으로 내린다.
- 버튼 글자는 **동사 한 덩어리**. `루틴으로 저장` → `루틴 저장`.

### 5.2 카드

- 배경 `카드색`, 모서리 `16`, **테두리·그림자 없음**.
- 카드는 **한 가지 얘기만** 담는다. 안에 구분선이 필요해지면 카드를 둘로 나눈다.
- 카드 제목은 본문 크기 + Bold. 제목 아래 `12`.

### 5.3 목록 한 줄

```
[아이콘]  이름                     값
          이름표                   단위
```

- 왼쪽 정렬 이름, 오른쪽 정렬 값. **값은 오른쪽 끝에 맞춘다** — 세로로 자릿수가 맞아야 비교된다.
- 줄 사이에 선을 긋지 않는다. 배경이 같으면 여백 `12`로 띄운다.
- 줄 전체가 누르는 영역이다. 줄 안에 또 버튼을 넣지 않는다(삭제는 선택 모드로).

### 5.4 숫자 입력

- 지금의 `−  [ 60 ]  +` 방식은 **유지한다.** 헬스장에서 키보드 올리는 것보다 빠르다.
- 다만 칸 높이를 `48`로 올리고, 숫자를 값 단계로 키운다.

### 5.5 빈 화면

- 빈 목록에 아무것도 안 그리지 않는다. **한 문장 + 주 버튼 하나.**
- 예: `아직 담은 음식이 없습니다` + `음식 추가`.

## 6. 화면별 검사표

고친 뒤 이 항목을 하나씩 세어본다. 하나라도 아니오면 안 고쳐진 것이다.

### 공통

- [ ] `OutlinedButton`이 화면에 하나도 없다
- [ ] 라임색이 두 곳 이하에만 있다
- [ ] `HorizontalDivider`가 없다
- [ ] 모든 것이 좌우 `20` 선에서 시작한다
- [ ] 글자 크기가 §3의 네 단계 안에만 있다
- [ ] 배경에 보라 틴트가 없다

### 오늘 / 식단

- [ ] 오늘 먹은 kcal이 화면에서 **제일 큰 글자**다
- [ ] 끼니 칸이 비었을 때 `음식 추가` 하나만 보인다 (`내 식사`는 글자 버튼)
- [ ] 목표 대비 진행이 막대 하나로 읽힌다

### 오늘 / 운동

- [ ] `운동 시작`이 유일한 주 버튼이다
- [ ] 운동 중일 때 경과 시간이 화면에서 제일 큰 글자다
- [ ] 세트 줄의 무게·횟수가 값 단계로 커졌다
- [ ] 루틴 이름이 한 줄에 들어간다 (안 접힌다)

### 히스토리

- [ ] 날짜 카드에서 kcal과 볼륨이 값 단계다
- [ ] 펼친 상세가 고정폭 글자 덩어리가 아니다 (복사용 텍스트는 `전체 복사`가 맡는다)

## 7. 작업 순서

**한 번에 다 갈아엎지 않는다.** 화면 하나를 끝까지 만들어 보고, 그게 마음에 들면 나머지를
거기 맞춘다. 여섯 화면을 동시에 고치면 여섯 개가 다 어중간해진다.

1. `Theme.kt`에 §2 색을 전부 박는다 (`surface`·`background`까지). **이것만으로 절반이 바뀐다**
2. 글자 네 단계를 `Typography`로 정의한다
3. 공용 부품(주 버튼 / 카드 / 목록 줄 / 값+이름표)을 `Widgets.kt`에 만든다
4. **운동 탭 하나만** 그 부품으로 다시 짠다 → 보고 결정
5. 통과하면 식단 → 히스토리 → 설정 → 내보내기 순
6. 각 단계마다 §6 검사표를 센다

---

## 8. 이 문서를 고칠 때

화면을 보고 "뭔가 이상한데"라는 말이 나오면, **그 이상함을 숫자나 규칙으로 바꿔서 여기
적는다.** 그게 안 되면 아직 무엇이 문제인지 모르는 것이고, 그 상태로 고치면 다음에 또 같은
말이 나온다.
